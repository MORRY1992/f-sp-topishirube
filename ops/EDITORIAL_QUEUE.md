# 編集候補 v2 の判定

この処理は収集した見出しと登録記事を整理するだけで、公式本文の照合・記事公開・運行状況判定は行わない。標準Pythonのみ。3時間間隔の既存収集から呼ばれ、追加のChatGPT自動化枠は不要。

## 出力と編集順

- `worklist`: 新規記事の作業候補。S/A/Bの見出し仮優先度は保持する。速報の事実確認済みを意味しない。
- `updateCandidates`: 既存記事との比較・更新候補。`articleIds`, `matchEvidence`, `updateSignals`を参照する。新規記事にせず公式本文と既存記事を比較し、重要差分がある場合のみ更新する。同じ内容なら追加不要。
- `alreadyCovered`: URL一致等の既報候補。ここでも`action`は本文比較と重要差分がある場合の更新を要求する。同じURLの本文が書き換わるため、自動で捨てない。
- `held`: 古い取得、失敗元、過去日の短期案内、対象期間不明、低優先度。関連記事があればそのIDは保持する。再取得・公式本文確認で再評価できる。
- `sourceChanges`: 取得成功時の出典ハッシュ変更。本文比較の合図であり、誤報や訂正の証拠ではない。

`counts.actionable`は新規作業候補数、`counts.updateCandidates`は更新確認数。総編集作業数と混同しない。既存の件数キーは維持。出力上限は新規20・更新20・既報100・保留500、判定入力は先頭500件。

## 既報・続報

1. 公式URLと`alternateUrls`を既存記事の出典URLと照合。追跡クエリとフラグメントを除き、URLエンコード差を吸収する。事象に意味のあるクエリパラメータは保持する。
2. URLが異なる場合も同じ公式ホスト内で、見出しと既存記事の見出し・要約・要点・fact節を照合。日付・定型句を除き表記を一部統一した2文字組の重なりを使う。少なくとも6組、候補の45%以上、かつ記事見出しと3組以上重なる場合に**関連題材の可能性**として更新確認へ回す。一般的なguide節は照合に使わない。
3. より新しい発表日ヒント、取得成功した出典のハッシュ変更、異なるURLでの関連題材、予約・料金・延期などの見出し語を更新シグナルとして残す。日付やハッシュだけで重要差分ありとは断定しない。

題材照合は汎用の完全な意味理解ではない。同じ公式ホストでも別事象を関連候補にする場合や、大きな言い換え・別ホストの公式PDFを見逃す場合がある。そのため自動削除・自動訂正には使わず、候補ID・URL・照合理由を残して編集判断する。候補同士の完全URL重複は既存collect.pyの処理を維持。

## 日付と失敗

- `sourcePublishedAt` / `announcementDate`: 情報源が発表日として提供した値。本文未照合のため`source-reported-unverified`。取得できなければnull / unknown。
- `sourceListedDate`: 一覧の先頭にある日付。正式発表日の確定値ではない。
- `firstSeenAt` / `lastSeenAt` / `collectedAt`: 発見・取得日時。発表日や対象年へ転用しない。
- `relevance.targetStartDate` / `targetEndDate`: 短期の運休・運転案内等の見出しから読める対象期間の**ヒント**。`basis`に推定根拠を残す。先頭の一覧日付は対象から除外する。
- 年なしの対象日は発表日または一覧日付の年を手掛かりにし、近接する年またぎを処理する。手掛かりがない、不正日付、未解決の相対日、終期が曖昧、当面・以降・繰り返しなどは保留する。
- 日本時間の当日と対象終日を比較する。当日・未来は本文確認候補、過去は`past-target-hint`で保留。開始日だけで期間終了としない。古い発表日だけを理由に、将来の新型列車運行開始などを失効扱いしない。
- `bodyVerified: false`, `autoPublish: false`, `operationalStatus: unknown`は全区分で維持。過去対象日の保留は復旧確認ではない。
- 取得後6時間超、未来の取得時計、403等の失敗、0件・parserWarningは成功扱いしない。既報照合できても失敗元の候補は保留。既存記事出典の監視失敗もhealthをdegradedにする。

## 検証

`npm test` → `npm run build` → `python scripts/check_links.py`。
実際の5候補と登録記事を固定した回帰入力は`tests/fixtures/editorial-20261026.json`。新しい記事・新しい収集結果が増えても、この入力で当初の誤判定が戻らないことを確認する。日時を固定しない再計算は6時間制限により保留になる場合がある。過去の取得時刻を現在へ書き換えて正常・新着と見せない。
